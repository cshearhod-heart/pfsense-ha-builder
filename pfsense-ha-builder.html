CARP: interfaces, virtual IPs, and real IPs

One entry per interface with a static IPv4 address. DHCP/PPPoE interfaces are listed but skipped — CARP needs a stable address on both boxes. Uncheck any interface that shouldn't get a CARP VIP.

VHIDs must be unique on the L2 segment, including any VRRP or CARP running on other devices — they share the 00:00:5e:00:01:xx MAC space. Defaults start at 10 to stay clear of group 1, the likeliest collision with an upstream router.

Advanced CARP defaults (advertising base, per-VIP password override)

Applies to all VIPs below. Pre-filled with a random value — replace it if you'd rather use your own.

Advertising skew is not editable on either side: the primary's is always 0 and the secondary's always +100 (capped at 254). That's what pfSense's own config-sync engine does to every CARP VIP each time it pushes config to the secondary, so the generated files match it from first boot rather than drifting once sync starts.

Dedicated SYNC interface (pfsync + config sync)

Per Heart's build standard: a dedicated interface on a direct firewall-to-firewall connection, carrying pfsync state sync and the XMLRPC config-sync channel. No default gateway on this interface.

Config synchronization (XMLRPC)

Configured on the primary only — pfSense recommends one-directional sync, so the secondary's "Synchronize Config to IP" is left blank in the generated file.

This must be a webConfigurator user with the same username/password on both firewalls. This tool records the intended credentials in the config — it does not create the user account.
